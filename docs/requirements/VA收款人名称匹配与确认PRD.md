# VA 收款人名称校验与确认 PRD

> 文档状态：待评审  
> 适用页面：商户端－新增收款人  
> 需求范围：收款人名称校验、提交前确认弹层  
> 核心约束：不新增或修改收款人状态；不改变原有新增收款人流程、审核流程和保存结果

## 1. 需求背景

B 绑定银行账户时，系统使用 B 侧留存的 KYC 名称，与客户填写的收款人名称进行比对。当前双方名称可能因大小写、空格、标点、连接词及公司类型缩写不同而未被正确识别。

客户侧统一包装为“收款行提供账户名称校验”：不解释内部名称来源，不出现 B 侧 KYC 名称或上游服务方。

本次仅补充：

1. 更完整的企业名称校验规则。
2. 客户点击“确认”后，仅在名称不一致时增加确认弹层。

## 2. 需求说明

### 2.1 触发时机

1. 客户完成新增收款人表单并点击“确认”。
2. 系统完成现有必填项校验后，使用 B 侧 KYC 名称与客户填写的收款人名称进行比较。
3. 名称一致：不展示弹层，直接沿用现有逻辑保存收款人。
4. 名称不一致：展示确认弹层。客户点击“确认并继续”后沿用现有逻辑保存；点击“返回修改”则关闭弹层并返回表单。

本需求不新增“已核验、待核验、不一致”等收款人状态，也不修改收款人原有状态流转。

## 3. 名称校验规则

### 3.1 标准化处理

两个名称使用相同规则处理后再比较，原始名称不修改、不回写。

| 序号 | 规则 | 示例 |
| --- | --- | --- |
| 1 | 忽略英文字母大小写 | `Acme` = `ACME` |
| 2 | 去除首尾空格；多个连续空格、Tab、换行合并为一个空格 | ` ACME  LTD ` = `ACME LTD` |
| 3 | 全角字符转换为半角字符 | `ＡＣＭＥ` = `ACME` |
| 4 | 忽略常见标点差异：句点、逗号、撇号、连字符、斜杠及括号 | `A.C.M.E.` = `A C M E` |
| 5 | 独立连接词 `AND` 与 `&` 等同 | `ACME AND CO` = `ACME & CO` |
| 6 | 拉丁字母忽略重音符号 | `CAFÉ` = `CAFE` |
| 7 | 公司类型使用等价词典转换 | `LIMITED` = `LTD` |
| 8 | 完成以上处理后再次合并空格，按词序比较 | — |

### 3.2 公司类型等价词典

仅当以下词语出现在名称末尾，且为完整单词或完整词组时进行转换。

| 标准写法 | 等价写法 |
| --- | --- |
| `LTD` | LIMITED, LTD, LTD. |
| `LLC` | LIMITED LIABILITY COMPANY, LLC, L.L.C. |
| `INC` | INCORPORATED, INC, INC. |
| `CORP` | CORPORATION, CORP, CORP. |
| `PLC` | PUBLIC LIMITED COMPANY, PLC, P.L.C. |
| `LLP` | LIMITED LIABILITY PARTNERSHIP, LLP, L.L.P. |
| `LP` | LIMITED PARTNERSHIP, LP, L.P. |
| `CO` | COMPANY, CO, CO. |
| `PTY LTD` | PROPRIETARY LIMITED, PTY LIMITED, PTY LTD |
| `PTE LTD` | PRIVATE LIMITED, PTE LIMITED, PTE LTD |
| `BV` | B.V., BV |
| `NV` | N.V., NV |

不同公司类型不等同，例如 `LLC ≠ LTD`、`PLC ≠ LTD`。

### 3.3 不做自动等同的情况

以下差异只提示客户核对，不自动判定为相同名称：

- 名称缺词、多词或词序不同。
- 企业简称与完整名称。
- 品牌名与法定名称。
- 母公司、子公司、分公司或集团名称。
- `GROUP`、`HOLDINGS`、`GLOBAL`、`INTERNATIONAL` 等主体词差异。
- 数字、罗马数字、地区或国家名称差异。
- 不同语言之间的翻译或音译。
- 仅字符串相似度较高，但不满足上述明确等价规则。

### 3.4 校验示例

| B 侧 KYC 名称 | 客户填写名称 | 校验结果 | 说明 |
| --- | --- | --- | --- |
| `ACME AND PARTNERS LIMITED` | `Acme & Partners Ltd.` | 一致 | 大小写、连接词及公司类型写法不同 |
| `CAFÉ GLOBAL LTD` | `CAFE GLOBAL LIMITED` | 一致 | 重音符号及公司类型写法不同 |
| `ABC HOLDINGS LTD` | `ABC LTD` | 存在差异 | 缺少 `HOLDINGS` |
| `ABC LLC` | `ABC LIMITED` | 存在差异 | 公司类型不同 |
| `GLOBAL ABC LTD` | `ABC GLOBAL LTD` | 存在差异 | 词序不同 |
| `ALPHA BETA COMPANY LTD` | `ABC LTD` | 存在差异 | 简称不能自动等同 |

## 4. 确认弹层

名称一致时不展示弹层。仅在名称存在差异时展示以下内容：

| 内容 | 文案/交互 |
| --- | --- |
| 标题 | 请核对收款人名称 |
| 提示 | 收款行返回的登记名称与您填写的收款人名称存在差异，请确认是否继续 |
| 返回名称 | 展示“收款行返回的登记名称” |
| 客户输入 | 展示“您填写的收款人名称” |
| 主按钮 | 确认并继续 |
| 次按钮 | 返回修改 |

### 4.2 交互规则

1. 弹层仅在名称不一致时触发，不区分“匹配成功”等其他弹层状态。
2. 客户勾选“我已核对以上名称，并确认继续绑定该银行账户”后，才可点击“确认并继续”。
3. 点击“确认并继续”后沿用现有保存逻辑；点击“返回修改”或关闭弹层时不保存，并保留表单内容。
4. 保存成功统一提示“收款人已保存”。
5. 客户侧统一描述为“收款行返回的登记名称”；不出现 A、VA 归属、B 侧 KYC、内部渠道、路由或费用信息。
6. 弹层确认结果不改变收款人状态。

## 6. 验收标准

1. 表 3.4 中的名称示例得到对应校验结果。
2. 名称一致时不展示弹层；名称存在差异时展示唯一的名称确认弹层。
3. 点击“返回修改”或关闭弹层时不保存，并保留客户已填写的表单内容。
4. 勾选确认后点击“确认并继续”，沿用现有新增收款人逻辑。
5. 本需求上线前后，收款人状态定义及状态流转保持不变。
6. 客户页面使用“收款行返回的登记名称”，不披露 A、VA 归属、B 侧 KYC、渠道、路由及费用信息。
