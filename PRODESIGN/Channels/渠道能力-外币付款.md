# 渠道能力：外币付款（法币）

> 日期：2026-08-04 ｜ 文档类型：渠道管理 / 产品需求
> 关联：`渠道能力-渠道基本信息与审批流程.md`（渠道基本信息、审批流、能力框架总纲）；`渠道能力-人民币结汇.md`；`渠道能力-数币付款.md`
> 交互稿：`渠道中心-外币付款.html`（渠道基本信息 + 外币付款）

---

## 一、定位

- 登记渠道的**外币付款能力**（corridor 登记），**不含路由策略**（优先级 / 成本 / 分流）。
- **一条数据 = 一个渠道 + 一种支付方式**（如 Nium + TT、Nium + Local Bank Transfer 各为一条）。
- **层级模型**：支付方式 → 清算系统（Rail，可多个）→ 国家。每个清算系统独立配置支持国家、币种、行业、资金来源、商户-收款人类型、时效、限额。
- **默认 + 例外（继承覆盖）**：清算系统层配一份默认能力，国家只挂清单；个别国家能力不同时在国家层做例外覆盖（一期是否实现待定，可先用多模块拆分替代）。

| 典型例子                                                   | 配置方式                                                                                    |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| Nium TT 支持 100 国，时效统一 T+1~T+3、限额一致            | 清算系统 = SWIFT，清算系统层配一份默认能力，国家只挂清单、不逐国配置                        |
| 菲律宾 PESONET：仅 PHP、仅 B2B / B2C、限额 2000 万 PHP、T0 | Local Bank Transfer 下 PESONET 独立一个清算系统模块，单独配国家 / 币种 / 类型 / 限额 / 时效 |

## 二、角色分工（不同的人维护不同的内容）

| 角色                                    | 维护内容                                                                                                                                        | 层级                           |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ |
| **FIBD**                          | **渠道基本信息**：渠道名称 / 主体 / 我司主体 / 所在国家 / 有效期 / 牌照 / 提供服务 / 附件（发起方）                                       | 渠道级                         |
| **合规（渠道合规运营 / 合规官）** | **合规政策**：商户主体所在国家、收款人所在国家（默认 = 商户）、支持 / 禁止行业、合规备注                                                | 渠道级，对该渠道下所有能力生效 |
| **渠道运营**                      | **渠道能力**：支付方式、清算系统模块（国家 / 币种 / 资金来源 / B2X / 时效 / 限额 / 超限处理）、收款人报备、POBO、收款人分类、商户主体国家 | 能力条目级（渠道 + 支付方式）  |
| **产品**                          | **账户体系**：账户要求（子账户 / VBA、VBA 收付范围）；**维护字段「是否参与过滤」的标签**（哪些字段参与渠道过滤）                    | 能力条目级 + 系统配置          |
| **清算（资金）**                  | **资金处理**：接受的打款币种、收款资金能否直接付款、付款失败资金退回规则                                                                  | 渠道级 / 能力级                |

> 各角色只能编辑自己负责的分区，各自操作自己的编辑按钮并提交，提交后同步其他人：
> - **基本信息工作流**：FIBD 发起 → 合规配置合规政策 → 完成同步 FIBD；
> - **能力工作流**：渠道运营发起 → 产品（账户体系）→ 清算（资金），每步完成同步上一步的人。能力列表操作拆为**编辑付款能力 / 编辑账户体系 / 编辑资金处理**三个入口。

## 三、字段两类用途

| 类型           | 说明                                                                                                 | 例子                                                             |
| -------------- | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **登记** | 仅供相关人明确知道渠道能力，无系统逻辑                                                               | 时效、限额、超限处理、账户要求、资金处理                         |
| **过滤** | 交易时参与过滤渠道，是渠道路由的第一部分（无具体路由策略）；**「是否参与过滤」标签由产品维护** | 支持国家 / 行业、支付方式、币种、资金来源、B2B / B2C / C2B / C2C |

## 五、表单结构（按维护角色分区）

**0. 合规政策（合规维护，渠道级，只读引用）→ 1. 基本信息（渠道运营）→ 2. 清算系统能力模块 × N（渠道运营）→ 3. 能力条目级公共字段（渠道运营）→ 4. 账户体系（产品）→ 5. 资金处理与异常（清算）**

### 5.0 合规政策（合规维护 · 渠道级）

> 在渠道维度维护一次，对该渠道所有能力生效；能力表单中**只读展示**，能力级国家 / 行业不得超出此范围（提交时校验）。

| 维度                      | 取值 / 规则                                            | 用途 |
| ------------------------- | ------------------------------------------------------ | ---- |
| **商户主体所在国家**（先配） | 支持（正向）/ 禁止（反向）只配一种 + 模糊搜索标签；作为母集 | 过滤 |
| **收款人所在国家** | 默认**同商户配置**；如范围不同则单独配置（支持 / 禁止） | 过滤 |
| **支持 / 禁止行业** | 货物贸易、服务贸易（备选跨境电商、广告营销、物流服务） | 过滤 |
| **备注** | 合规备注 | 登记 |

> **渠道基本信息工作流**：FIBD 新增 / 维护基本信息 → 通知合规配置合规政策 → 合规提交后同步 FIBD。列表操作拆为**基本信息编辑 / 合规政策编辑**两个入口，各自独立提交。

### 5.1 基本信息（渠道运营 · 决定这条数据）

| 维度               | 取值 / 规则                                                                                 | 用途 |
| ------------------ | ------------------------------------------------------------------------------------------- | ---- |
| **选择渠道** | 从已建基本信息的渠道中选择，回显**渠道 code**；**编辑时不可修改**               | 过滤 |
| **支付方式** | 单选：**TT、LOCAL BANK TRANSFER、WALLET**；与渠道构成唯一键，**编辑时不可修改** | 过滤 |
| 服务时间           | 工作日 / 自然日 单选 + 起止时间段；默认 7\*24                                               | 登记 |
| **备注**     | 自由备注（基本信息备注）                                                                    | 登记 |

### 5.2 清算系统能力模块（渠道运营 · 1~N 个，每个 rail 独立）

> TT 默认单一模块（SWIFT）；LOCAL BANK TRANSFER 可添加多个清算系统模块（CHATS、FPS、SEPA、SEPA Instant、ACH、PESONET、InstaPay 等，每个国家的清算系统做基础数据）。

| 维度                                 | 取值 / 规则                                                                                                                                        | 用途 |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ---- |
| **收款国家（收款人所在国家）** | 该清算系统支持的国家清单；支持 / 禁止只配一种 + 模糊搜索标签；不得超出渠道级合规政策；TT 可挂大量国家，本地清算系统通常 1 个或少数国家             | 过滤 |
| **收款人账户币种**             | 可多选（JPY / USD / EUR / SGD / GBP / PHP 等）；结算币种在渠道账户模块维护                                                                         | 过滤 |
| **支持的行业分类**             | 货物贸易、服务贸易；不得超出渠道级合规政策 - 暂不支持                                                                                              | 过滤 |
| **支持的资金来源**             | 平台结算款（→选电商平台）/ 线下贸易款 / 三方收单行结算款（→选收单行）- 暂不支持                                                                  | 过滤 |
| **商户-收款人类型**            | 可多选：B2B、B2C、C2B、C2C（如 PESONET 仅 B2B / B2C）                                                                                              | 过滤 |
| **到账时效**                   | 单选：T+n / n 小时 / 下一工作日 / 当天 / 实时                                                                                                      | 登记 |
| **支付限额（渠道限额）**       | 收款人账户币种 × 商户-收款人类型 表格，每格单笔 / 单日限额（最大最小，默认无限额）；完整维度 = 清算系统 + 币种 + B2X + 收款人类型 + 行业分类 组合 | 登记 |
| **超限处理方式**               | 自由文本输入，仅作登记；系统不据此自动执行                                                                                                         | 登记 |
| **国家例外覆盖**（可选）       | 个别国家能力不同时在国家层覆盖（币种 / 时效 / 限额）；一期待定                                                                                     | 登记 |

### 5.3 能力条目级公共字段（渠道运营 · 对所有清算系统生效）

| 维度                                 | 取值 / 规则                                                                                                | 用途 |
| ------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ---- |
| **商户主体所在国家**           | 独立配置、不跟随收款人国家；支持 / 禁止只配一种 + 模糊搜索标签                                             | 过滤 |
| **收付款人关系（收款人分类）** | 可多选：同名 / 异名；异名场景（股东、关联公司、供应商、广告服务商、物流服务商、员工、其他）推送渠道时映射  | 过滤 |
| **收款人报备开户**             | 需要 / 不需要；选「需要」出现文本框填写报备资料清单                                                        | 登记 |
| **是否支持 POBO**              | 按 B2B / B2C / C2B / C2C 分别配置支持 / 不支持，仅对已勾选类型生效；POBO 要求：只能用入网商户信息 / 自定义 | 登记 |
| **备注**                       | 自由备注（基本能力备注）                                                                                   | 登记 |

### 5.4 账户体系（产品维护）

| 维度                   | 取值 / 规则                                                                                                                      | 用途     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------- |
| **账户要求**     | 付款前需先创建的账户形态：创建子账户 / 使用单独的付款 VBA；VBA 使用范围：仅用于付款 / 收付一体（影响账户结构设计和资金归集方式） | 登记     |
| **过滤标签维护** | 产品维护各字段「是否参与渠道过滤」的标签（系统配置，非逐条能力配置）                                                             | 系统配置 |

### 5.5 资金处理与异常处理（清算维护 · 登记）

> 整段仅作登记备案，系统不据此自动处理；有独立备注。

| 维度                       | 取值 / 规则                                                                           |
| -------------------------- | ------------------------------------------------------------------------------------- |
| **接受的打款币种**   | 渠道可接受我司打款的币种（如：只能接受 USD 打过去）                                   |
| **收款资金直接付款** | 是否支持收款资金直接用于付款（收付一体）/ 需先归集后再付                              |
| **付款失败资金退回** | 退回到：大账户 / 商户账户                                                             |
| **退回币种**         | 多选：渠道结算币种 / 收款人账户币种 / 付款钱包币种 / 自定义币种；仅登记，无优先级判断 |
| **退回金额**         | 单选：原金额 / 去掉手续费金额；选「去掉手续费金额」出现备注输入框（手续费预计多少）   |
| **备注**             | 自由备注（异常处理独立备注）                                                          |

## 六、验收标准

- 一条数据 = 渠道 + 支付方式；编辑时渠道与支付方式均不可修改；
- 支付方式下按清算系统分模块配置，每模块独立维护国家 / 币种 / 行业 / 资金来源 / B2X / 时效 / 限额 / 超限处理；TT 单一模块可挂大量国家统一配置；
- 表单按角色分区：合规政策（合规，只读引用）/ 渠道能力（渠道运营）/ 账户体系（产品）/ 资金处理（清算）；各角色只能编辑自己负责的分区；
- 字段区分登记 / 过滤两类用途，页面以角标标识；「是否参与过滤」标签由产品维护；
- 能力级国家 / 行业不得超出渠道级合规政策（提交时校验）；
- 支付限额按 清算系统 + 币种 + B2X + 收款人类型 + 行业分类 组合生效；超限处理为自由文本、仅登记；
- 收款人报备开户选「需要」可填写报备资料；POBO 按 B2X 分别配置；
- 资金处理可登记接受的打款币种 / 收款资金是否可直接付款 / 失败退回规则（位置 / 币种多选 / 金额单选）；
- 基本信息、基本能力、异常处理各有独立备注。
