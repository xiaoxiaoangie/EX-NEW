## 一、定位

- 在**外币付款结构基础上**追加「申报人与申报资料」与「结汇明细配置」段；收款国家仅限**外汇管制国家**；若渠道同时支持非管制国家，在「外币付款」中单独维护。
- **一条数据 = 一个渠道 + 一种支付方式**；层级模型、默认 + 例外、登记 / 过滤两类用途 与外币付款一致（见外币付款文档）。
- **互斥规则**：同一渠道 + 同一国家，人民币结汇与外币付款只能存在一条能力，提交时系统校验并阻断冲突。

## 二、角色分工

与外币付款一致（合规 = 合规政策；渠道运营 = 渠道能力 + 申报场景；产品 = 账户体系 + 过滤标签；清算 = 资金处理 + 结汇明细配置〔库表〕）。

## 三、列表

外币付款列基础上增加**申报人要求**列：渠道 code / 渠道名称 / 支付方式 / 清算系统 / 覆盖国家数 / 已启用场景 / 申报人要求 / 状态 / 更新时间。

## 四、表单结构（按维护角色分区）

**0. 合规政策（合规 · 只读引用）→ 1. 基本信息（渠道运营，同外币付款 5.1，收款国家仅限外汇管制国家）→ 2. 申报人与贸易场景（渠道运营）→ 3. 结汇明细配置（清算 · 库表维护，不在页面配置）→ 4. 清算系统能力模块（渠道运营，同外币付款 5.2）→ 5. 能力条目级公共字段（渠道运营，同外币付款 5.3）→ 6. 账户体系（产品，同外币付款 5.4）→ 7. 资金处理与异常（清算，同外币付款 5.5）**

### 4.1 申报人与贸易场景（明细来源类型）

> 按场景逐行配置，**仅「启用」的行为有效能力**；启用场景 = 订单贸易场景准入（过滤）；行内申报编码 / 贸易背景 / 申报人要求 = 该场景下的材料收集规则（处理）。
> 申报人国家 = 收款人所在国家（默认中国大陆，不展示、不配置）。

**公共枚举**

- **申报编码**：122030、121010
- **贸易背景资料（多选）**：订单明细、合同、PI、物流/快递、报关单、银行流水、交付物凭证
- **申报人要求**：证件类型（身份证 / 护照 / 营业执照）+ 申报人类型（个人 / 企业）——**每行（在线类与线下类）均需配置**

**在线类（明细来源类型）**

| 明细来源类型 | 附加字段 | 配置内容 |
| --- | --- | --- |
| **1. 平台结算** | 平台（电商 / 游戏 / 应用市场，如 Amazon / Shopee / TikTok Shop / App Store / Google Play）+ 站点（US / JP / SG / 全站点） | 申报编码 + 贸易背景多选 + 申报人要求 |
| **2. 独立站** | 独立站名称 + 收单机构（PayPal / Stripe / Airwallex 等） | 申报编码 + 贸易背景多选 + 申报人要求 |
| **3. 游戏平台** | 应用市场名称 + 收单机构 | 贸易背景多选 + 申报人要求 |
| **4. 游戏充值站 / 网游** | 收单机构 | 申报编码 + 贸易背景多选 + 申报人要求 |
| **5. 电商自建站** | 收单机构 | 申报编码 + 贸易背景多选 + 申报人要求 |
| **6. 广告联盟** | 平台 / 应用市场 + 收单机构 | 申报编码 + 贸易背景多选 + 申报人要求 |

**线下类（明细来源类型）**

| 明细来源类型 | 规则 |
| --- | --- |
| **1. B2B 货贸** | **可按申报编码拆多行**，不同申报编码对应不同背景材料（如 121010 → 报关单；122030 → PI + 物流/快递）；**行内多选 = OR，多行之间 = AND**；+ 申报人要求 |
| **2. 广告服务** | 申报编码 + 贸易背景多选（合同、交付物凭证、银行流水等）+ 申报人要求 |
| **3. 薪资下发** | 申报编码 + 贸易背景多选（合同、银行流水等）+ 申报人要求 |
| **4. 佣金下发** | 申报编码 + 贸易背景多选（合同、交付物凭证、银行流水等）+ 申报人要求 |

**派生规则**：支持的资金来源由启用场景自动推导（在线类 → 平台结算款；含收单机构的在线类 → 三方收单行结算款；线下类 → 线下贸易款），只读。

### 4.2 结汇明细配置（清算 · 数据库配置表维护，不在渠道中心页面配置）

> 明细 = 结汇资金的逐笔来源记录（平台回款 / 收单行结算等）；仅影响单笔结汇申报执行，不参与渠道过滤。

| 维度 | 取值 / 规则 |
| --- | --- |
| **明细支持的币种** | 可多选（USD / EUR / GBP / HKD / SGD / JPY / AUD 等）；明细原始币种不在范围内视为不支持币种 |
| **不支持币种处理方式** | 单选：拒绝该笔明细 / 换汇为支持币种后结汇 / 人工处理 |
| **明细关键字匹配** | 多条规则：匹配字段（打款方名称 / 交易摘要 / 参考号）+ 匹配方式（包含 / 精确 / 前缀）+ 关键字 → 匹配结果（平台 / 资金来源）；命中即归类，未命中转人工 |
| **明细与下发推送关系** | 关联关系：1:1 / 1:N / N:1；金额校验：下发金额 = Σ 关联明细 / ≤ Σ 关联明细；推送时机：下发时逐笔推送 / 明细先行报备、下发时引用 |
| **备注** | 自由备注（明细配置独立备注） |

## 五、验收标准

- 人民币结汇为独立能力模块，收款国家仅限外汇管制国家；与外币付款互斥（同渠道 + 同国家只能存在一条）；
- 贸易背景申报按明细来源类型逐行配置，分在线类（6 种）与线下类（4 种）；每行均配置申报人要求；B2B 货贸支持多行 + 行内多选，行内 = OR、行间 = AND；
- 申报人国家默认中国大陆，不展示、不配置；
- 资金来源由启用场景自动推导，只读；
- 结汇明细配置由技术 / 清算在数据库配置表维护，不在渠道中心页面配置；
- 其余结构（清算系统模块 / 公共字段 / 账户体系 / 资金处理）与外币付款验收标准一致；
- 基本信息、基本能力、申报信息、明细配置、异常处理各有独立备注。
