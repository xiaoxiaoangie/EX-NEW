## 一、定位

- 登记渠道的**数币付款能力**，不含路由策略。
- 一条数据 = 渠道 + 收款方式（收款地址 / 数币钱包）。
- 登记 / 过滤两类字段用途与外币付款一致；「是否参与过滤」标签由产品维护。

## 二、角色分工

与外币付款一致：合规 = 合规政策（支持 / 禁止国家、行业）；渠道运营 = 数币能力（网络币种 / 地址类型 / 限额 / 承兑）；产品 = 账户体系 + 过滤标签；清算 = 资金处理。

## 三、列表

渠道 / 收款方式 / 网络 · 币种 / 地址类型 / 限额规则 / 是否承兑 / 状态 / 更新时间。

## 四、字段定义

| 维度 | 取值 / 规则 | 维护角色 | 用途 |
| --- | --- | --- | --- |
| **所属渠道** | 从已建基本信息的渠道中选择 | 渠道运营 | 过滤 |
| **收款方式** | 收款地址 / 数币钱包 | 渠道运营 | 过滤 |
| **商户主体所在国家** | 支持（正向）/ 禁止（反向）只配一种 + 模糊搜索标签；不得超出渠道级合规政策 | 渠道运营 | 过滤 |
| **网络 / 币种** | 支持的区块链网络、币种清单（TRC20-USDT / ERC20-USDT / BEP20-USDT / ERC20-USDC 等） | 渠道运营 | 过滤 |
| **收款地址类型** | 客户自有钱包地址 / 渠道生成地址 | 渠道运营 | 登记 |
| **支付限额** | 按网络 / 币种组合配置（最大最小） | 渠道运营 | 登记 |
| **超限处理方式** | 自由文本输入，仅作登记 | 渠道运营 | 登记 |
| **是否支持承兑** | 数币直接付款 / 需要先承兑为法币再付 | 渠道运营 | 登记 |
| **账户要求** | 数币钱包 / 地址的账户形态要求 | 产品 | 登记 |
| **资金处理** | 接受的打款币种（法币 / 数币）、失败退回规则（同外币付款 5.5） | 清算 | 登记 |
| **备注** | 自由备注（基本能力备注，独立于异常处理备注） | 渠道运营 | 登记 |

## 五、验收标准

- 数币付款独立维护，一条数据 = 渠道 + 收款方式；
- 网络 / 币种、限额按组合配置；承兑登记数币直付或先承兑为法币；
- 表单按角色分区（合规 / 渠道运营 / 产品 / 清算），各角色只能编辑自己负责的分区；
- 字段区分登记 / 过滤两类用途，页面以角标标识。
