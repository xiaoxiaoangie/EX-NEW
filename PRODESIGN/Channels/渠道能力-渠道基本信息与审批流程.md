# 渠道能力：渠道基本信息、审批流程与能力维度

> 日期：2026-07-28 ｜ 文档类型：渠道管理 / 产品需求
> 关联：`EX OffRamp解决方案.md` 的 Case 5（渠道能力维护）引用本文档；本文档定义 **渠道基本信息（签约信息）模块**、**渠道信息的审批 / 变更流程** 与 **渠道能力（付款）维度**；渠道账户模块不在本文档展开。
> 交互稿：`渠道中心.html`（本文档结构与交互稿对应：侧边栏 = 渠道基本信息 / 渠道能力〔外币付款、人民币结汇、数币付款〕/ 渠道账户；模块可独立新增：新渠道先建基本信息再建能力，已有渠道可直接新增能力，能力 ≠ 必须建账户）。

## 一、定位

渠道信息管理拆为三个独立模块：

| 模块                                  | 内容                                                             | 文档             |
| ------------------------------------- | ---------------------------------------------------------------- | ---------------- |
| **① 渠道基本信息（签约信息）** | 渠道主体、我司主体、签约有效期、渠道提供服务、渠道牌照、附件协议 | **本文档** |
| **② 渠道能力**                 | 付款（法币 / 数币 / 人民币结汇）能力维度 + 异常处理              | **本文档** |
| **③ 渠道账户**                 | 渠道账户结构与账户维度                                           | 单独设计（后补） |

---

## 二、渠道整体流程（签约 → 维护 → 变更）

1. **FIBD 商务签约**：FIBD 完成商务谈判与签约，**确认渠道基本能力**（主体、牌照、服务范围）。
2. **渠道运营维护**：渠道运营基于签约结果，维护渠道**基本信息与具体能力**。
3. **信息变动流程**：渠道信息 / 能力变动后，需**同步产品经理、渠道运营、清算（对账）、合规、FIBD**；改动须走审批流（见第三节）。

---

## 三、渠道基本信息（签约信息）

### 3.1 字段定义

| 字段                   | 说明                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| **渠道名称**     | 渠道名称（如 ChannelPay），列表与能力模块均以此展示                                              |
| **渠道主体**     | 渠道签约的法律主体                                                                               |
| **我司主体**     | 我司签约主体（下拉选择）                                                                         |
| **渠道所在国家** | 渠道注册 / 展业所在国家；国家枚举值多，采用**模糊搜索 + 标签**选择                         |
| **签约有效期**   | 合同起止日期                                                                                     |
| **渠道提供服务** | 渠道实际提供的服务范围，多选：**法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** |
| **渠道牌照**     | 渠道持有的牌照                                                                                   |
| **附件**         | 协议、补充协议等文件（非必填）                                                                   |

> **服务范围说明**：「渠道提供服务」是该渠道的能力清单上限——签约时确认的服务项，决定「渠道能力」模块中哪些能力允许维护；能力维度明细在能力模块中维护，本字段只做服务级勾选；

### 3.2 修改流程（基本信息审批流）

- **渠道运营修改 → FIBD Head 审批 → 合规审批、法务审批**。
- 基本信息（主体、牌照、有效期、服务范围）属**法律与合规层面信息**，必须经合规与法务审批后才生效。

---

## 四、渠道能力变动审批流

> 能力维度变动（如新增收款国家、调整限额、变更 POBO 规则等）走独立的审批流，与基本信息审批流分开。

- **渠道运营发起 → FIBD Head 审批** → 审批通过后**同步给合规、产品、清算**。
- 变动生效后同步范围：**产品经理、渠道运营、清算（对账）、合规、FIBD**。

### 两类审批流对比

| 项目                 | 渠道基本信息              | 渠道能力             |
| -------------------- | ------------------------- | -------------------- |
| **发起人**     | 渠道运营/ FIBD            | 渠道运营             |
| **审批人**     | FIBD Head → 合规 → 法务 | FIBD Head            |
| **审批后同步** |                           | 合规、产品、清算     |
| **性质**       | 法律 / 合规信息，重审批   | 业务运营信息，重同步 |

## 五、渠道能力（付款，分三类 + 异常处理）

> **范围**：本期只做「付款」渠道能力维护；收款、换汇能力后补。付款能力拆为 **外币付款（法币）/ 数币付款 / 人民币结汇（外汇管制国家）** 三类 + **异常处理**，与交互稿侧边栏一一对应。
> **数据粒度（外币付款 / 人民币结汇）**：一条数据 = 一个渠道 code + 一个国家（支持模式）或一个渠道 code + 该付款方式下的禁止国家清单（禁止模式）+ 一个付款方式。
> **备注规则**：基本信息、付款能力、异常处理、人民币结汇申报信息 **各自有独立的备注字段**。

### 5.1 外币付款（法币付款）

**列表**：渠道 code / 渠道名称 / 付款方式 / 收款国家（支持 / 禁止标识）/ 备注 / 更新时间。

**表单分三段（与交互稿一致）：1. 基本信息 → 2. 付款能力 → 3. 异常处理（见 5.4）**

#### 5.1.1 基本信息

| 维度                                 | 取值 / 规则                                                                                                                                                     |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **选择渠道**                   | 从已建基本信息的渠道中选择，选中后回显**渠道 code**；**编辑时渠道不可修改**                                                                         |
| **收款国家（收款人所在国家）** | 支持**支持国家（正向）/ 禁止国家（反向）** 两种配置模式，**只配置一种即可**；国家枚举值多，采用**模糊搜索 + 标签**而非全量勾选                |
| **收款方式（付款方式）**       | **单选**：**TT、LOCAL BANK TRANSFER、WALLET**                                                                                                       |
| 支付/清算系统                        | 仅当收款方式 =**LOCAL BANK TRANSFER** 时启用：**CHATS、FPS、SEPA、SEPA Instant、ACH** 等<br />- 每个国家的支付/清算系统做基础数据<br />- 暂时不支持 |
| 服务时间                             | **工作日 / 自然日** 单选 + 起止时间段；默认 7\*24（自然日 00:00-23:59）                                                                                   |
| **备注**                       | 自由备注（基本信息备注）                                                                                                                                        |

#### 5.1.2 付款能力

| 维度                                 | 取值 / 规则                                                                                                                                                                                                                                                           |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **商户主体所在国家**           | 商户主体注册国家；**独立配置、不跟随收款人国家**，交互与收款国家一致：支持**支持（正向）/ 禁止（反向）只配一种** + 模糊搜索标签                                                                                                                           |
| **收付款人关系（收款人分类）** | 可多选：**同名 / 异名**；异名的具体场景（**股东、关联公司、供应商、广告服务商、物流服务商、员工、其他**）在推送渠道时映射                                                                                                                                 |
| **商户-收款人类型**            | 可多选：**B2B、B2C、C2B、C2C**（= 商户类型 → 收款人类型组合，与商户类型、收款人类型一起维护）                                                                                                                                                                  |
| **账户要求**                   | 付款前需要先创建的账户形态：**创建子账户 / 使用单独的付款 VBA**；VBA 的使用范围：**仅用于付款 / 收付一体**（两者影响账户结构设计和资金归集方式）                                                                                                          |
| **支持的行业分类**             | **货物贸易、服务贸易**（交互稿另备选跨境电商、广告营销、物流服务）- 暂不支持                                                                                                                                                                                    |
| **支持的资金来源**             | **平台结算款**（→ 选电商平台）；**线下贸易款**（无子选项）；**三方收单行结算款**（→ 选三方收单行，如 PayPal / Stripe / Airwallex 等）<br />- 资金来源暂不支持                                                                                     |
| **收款人报备开户**             | 收款人**是否需要报备开户**：**需要 / 不需要**；选「需要」出现**文本框**，填写报备所需资料清单                                                                                                                                                       |
| **收款人账户币种**             | 可多选（JPY / USD / EUR / SGD / GBP 等）；**结算币种在渠道账户模块单独维护，不在此处配置**                                                                                                                                                                      |
| **到账时效**                   | 单选：**T+n / n 小时 / 下一工作日 / 当天 / 实时**                                                                                                                                                                                                               |
| **支付限额（渠道限额）**       | 交互稿以**收款人账户币种 × 商户-收款人类型（B2B / B2C / C2B / C2C）** 表格配置，每格单笔 / 单日限额（**最大最小**，默认无限额）；完整维度 = 按**收款方式 + Rails + 币种 + 商户-收款人类型 + 收款人类型 + 行业分类** 组合配置（不同组合限额可不同） |
| **是否支持 POBO**              | **按商户-收款人类型（B2B / B2C / C2B / C2C）分别配置支持 / 不支持**，仅对上方已勾选的商户-收款人类型生效；POBO 要求：**只能用入网商户信息 / 自定义**                                                                                                      |
| **备注**                       | 自由备注（基本能力备注，独立于异常处理备注）                                                                                                                                                                                                                          |

### 5.2 数币付款

| 维度                       | 取值 / 规则                                                                               |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| **所属渠道**         | 从已建基本信息的渠道中选择                                                                |
| **收款方式**         | **收款地址 / 数币钱包**                                                             |
| **商户主体所在国家** | 独立配置，交互与外币付款一致：**支持（正向）/ 禁止（反向）只配一种** + 模糊搜索标签 |
| **网络 / 币种**      | 支持的区块链网络、币种清单（TRC20-USDT / ERC20-USDT / BEP20-USDT / ERC20-USDC 等）        |
| **收款地址类型**     | 客户自有钱包地址 / 渠道生成地址                                                           |
| **支付限额**         | 按网络 / 币种组合配置（最大最小）                                                         |
| **是否支持承兑**     | 数币直接付款 / 需要先承兑为法币再付                                                       |
| **备注**             | 自由备注（基本能力备注，独立于异常处理备注）                                              |

### 5.3 人民币结汇

> 交互与外币付款一致，在其基础上**追加「申报人与申报资料」与「结汇明细配置」段**。表单分五段：**1. 基本信息（同 5.1.1，收款国家仅限外汇管制国家；若渠道同时支持非管制国家，在「外币付款」中单独维护）→ 2. 申报人与申报资料 → 3. 结汇明细配置（明细表）→ 4. 付款能力（同 5.1.2）→ 5. 异常处理（同 5.4）**。列表在外币付款列基础上增加**申报人要求**列。

**公共枚举**

- **申报编码**：122030、121010
- **贸易背景（多选）**：订单明细、合同、PI、物流/快递、报关单、银行流水、交付物凭证

**贸易背景申报 · 在线类（明细来源类型）**

> 在线类每行同样需配置**申报人要求**：证件类型（身份证 / 护照 / 营业执照）+ 申报人类型（个人 / 企业）。

| 明细来源类型                   | 附加字段                                                                                                                          | 申报编码 + 贸易背景要求 + 申报人要求 |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| **1. 平台结算**          | 平台（电商平台 / 游戏平台 / 应用市场，如 Amazon / Shopee / TikTok Shop / App Store / Google Play）+ 站点（US / JP / SG / 全站点） | 申报编码 + 贸易背景多选 + 申报人要求 |
| **2. 独立站**            | 独立站名称 + 收单机构（PayPal / Stripe / Airwallex 等）                                                                           | 申报编码 + 贸易背景多选 + 申报人要求 |
| **3. 游戏平台**          | 应用市场名称 + 收单机构                                                                                                           | 贸易背景多选 + 申报人要求            |
| **4. 游戏充值站 / 网游** | 收单机构                                                                                                                          | 申报编码 + 贸易背景多选 + 申报人要求 |
| **5. 电商自建站**        | 收单机构                                                                                                                          | 申报编码 + 贸易背景多选 + 申报人要求 |
| **6. 广告联盟**          | 平台 / 应用市场 + 收单机构                                                                                                        | 申报编码 + 贸易背景多选 + 申报人要求 |

**贸易背景申报 · 线下类（明细来源类型）**

> 线下类每行同样需配置**申报人要求**：证件类型（身份证 / 护照 / 营业执照）+ 申报人类型（个人 / 企业）。

| 明细来源类型          | 规则                                                                                                                                                                                      |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **1. B2B 货贸** | **可按申报编码拆多行**，不同申报编码对应不同背景材料（如 121010 → 报关单；122030 → PI + 物流/快递）；**行内多选 = OR，多行之间 = AND**；申报人要求（证件类型 + 申报人类型） |
| **2. 广告服务** | 申报编码 + 贸易背景多选（合同、交付物凭证、银行流水等）+ 申报人要求（证件类型 + 申报人类型）                                                                                              |
| **3. 薪资下发** | 申报编码 + 贸易背景多选（合同、银行流水等）+ 申报人要求（证件类型 + 申报人类型）                                                                                                          |
| **4. 佣金下发** | 申报编码 + 贸易背景多选（合同、交付物凭证、银行流水等）+ 申报人要求（证件类型 + 申报人类型）                                                                                              |

**结汇明细配置（明细表，参考 IPL 既有配置，独立于贸易背景申报单独维护）**

> 明细 = 结汇资金的逐笔来源记录（平台回款 / 收单行结算等）。

| 维度                         | 取值 / 规则                                                                                                                                                                                                                          |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **明细支持的币种**     | 可多选（USD / EUR / GBP / HKD / SGD / JPY / AUD 等）；明细原始币种不在范围内视为不支持币种                                                                                                                                           |
| **不支持币种处理方式** | 单选：**拒绝该笔明细 / 换汇为支持币种后结汇 / 人工处理**                                                                                                                                                                       |
| **明细关键字匹配**     | 多条规则：匹配字段（**打款方名称 / 交易摘要 / 参考号**）+ 匹配方式（**包含 / 精确 / 前缀**）+ 关键字 → 匹配结果（平台 / 资金来源）；命中即归类，未命中转人工处理                                                        |
| **明细与下发推送关系** | 关联关系：**1:1（一明细一下发）/ 1:N（一明细拆多笔下发）/ N:1（多明细合并一笔下发）**；金额校验：**下发金额 = Σ 关联明细 / 下发金额 ≤ Σ 关联明细**；推送时机：**下发时逐笔推送明细 / 明细先行报备、下发时引用** |
| **备注**               | 自由备注（**明细配置独立备注**）                                                                                                                                                                                               |

### 5.4 异常处理

> 针对付款失败后的资金退回规则；**异常处理有独立的备注字段**。

| 维度                       | 取值 / 规则                                                                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **付款失败资金退回** | 退回到：**大账户 / 商户账户**                                                                                                                                     |
| **退回币种**         | **多选**：渠道结算币种 / 收款人账户币种 / 付款钱包币种 / **自定义币种**；多选**仅作登记，无优先级判断**                                               |
| **退回金额**         | **单选**：**原金额** / **去掉手续费金额**；选「去掉手续费金额」出现一个**备注输入框**（不是手续费金额字段），供运营填写**手续费预计多少** |
| **备注**             | 自由备注（**异常处理独立备注**）                                                                                                                                  |

### 5.5 配置层级（树状，与交互稿侧边栏对应）

- **渠道基本信息**：渠道名称 / 渠道主体 / 我司主体 / 渠道所在国家 / 有效期 / 服务 / 渠道牌照 / 附件（修改走 FIBD Head + 合规 + 法务审批）
- **渠道能力 → 付款** → 拆为三类 + 异常处理
  - **外币付款（法币）** → 基本信息（选择渠道回显 code / 收款国家支持或禁止 / 付款方式单选 / Rails / 服务时间 / 备注）+ 付款能力（商户主体所在国家支持或禁止 / 收款人分类 / 商户-收款人类型 / **账户要求** / 行业分类 / 资金来源 / **收款人报备开户** / 收款人账户币种 / 到账时效 / 限额（多维联动）/ POBO / 备注）+ 异常处理
  - **数币付款** → 所属渠道 / 收款地址 / 数币钱包 / 商户主体所在国家 / 网络币种 / 地址类型 / 限额 / 承兑 / 备注
  - **人民币结汇（外汇管制国家）** → 外币付款全部 + 申报人国家（默认中国大陆，不展示）+ 申报人证件类型 + 贸易背景申报（在线类 / 线下类明细来源）+ 结汇明细配置（明细支持币种 / 不支持币种处理 / 关键字匹配 / 明细与下发推送关系 / 明细备注）+ 申报备注
  - **异常处理** → 资金退回位置 / 退回币种（多选）/ 退回金额（单选）/ 手续费备注 / 异常备注
- **渠道账户**：由**资金同学**新增，新增后**同步清算**；交互稿已含基础字段（所属渠道 / 账户形态〈子账户、付款 VBA 仅付款或收付一体〉/ 账户号 / 币种 / 用途 / 备注），详细方案单独设计（后补）

## 六、验收标准

- 渠道基本信息可维护 **渠道名称 / 渠道主体 / 我司主体 / 渠道所在国家 / 签约有效期 / 渠道提供服务 / 渠道牌照 / 附件**；
- 「渠道提供服务」为 **法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** 六项多选；
- 付款能力可拆为 **外币（法币）/ 数币 / 人民币结汇** 三类分别维护，异常处理随表单维护；外币付款 / 人民币结汇一条数据 = 渠道 code + 国家（或禁止国家清单）+ 付款方式；编辑时渠道不可修改；
- 法币付款可维护 **账户要求**（子账户 / VBA，VBA 仅付款 / 收付一体）；
- **付款方式单选，= LOCAL BANK TRANSFER 才出现清算系统**；资金来源选「平台结算款 / 三方收单行结算款」时出现对应子选择；
- 服务时间可维护 **工作日 / 自然日 + 起止时间段**（默认 7\*24）；到账时效可维护 T+n / n 小时 / 下一工作日 / 当天 / 实时；
- 人民币结汇为独立能力模块（收款国家仅限外汇管制国家），在外币付款基础上追加申报人与申报资料段；申报人国家**默认中国大陆，不展示、不配置**；
- 贸易背景申报按**明细来源类型**逐行配置，分**在线类**（平台结算 / 独立站 / 游戏平台 / 游戏充值站网游 / 电商自建站 / 广告联盟）与**线下类**（B2B 货贸 / 广告服务 / 薪资下发 / 佣金下发）；**在线类与线下类每行均配置申报人要求**（证件类型 + 申报人类型）；B2B 货贸支持 **多行 + 行内多选**，行内 = OR、行间 = AND；
- 是否支持 POBO 按 **商户-收款人类型（B2B / B2C / C2B / C2C）** 分别配置支持 / 不支持；
- 人民币结汇可维护**结汇明细配置（明细表）**：明细支持币种（多选）/ 不支持币种处理方式（单选）/ 明细关键字匹配（多条规则，命中归类、未命中转人工）/ 明细与下发推送关系（关联关系 + 金额校验 + 推送时机），明细配置有独立备注；
- 收款国家与商户主体所在国家均可按 **支持国家（正向）/ 禁止国家（反向）** 配置，同一字段只配一种模式；
- 支付限额可按 **收款方式 + Rails + 币种 + 商户-收款人类型 + 收款人类型 + 行业分类** 组合生效（最大最小），不同组合限额可不同；
- 法币付款可维护 **收款人报备开户**（需要 / 不需要）；选「需要」可填写报备所需资料；
- 异常处理可维护 **退回位置 / 退回币种（多选，仅作登记、无优先级判断）/ 退回金额（单选）**；选「去掉手续费金额」出现备注输入框；
- 基本能力、异常处理、人民币结汇申报信息 **各有独立备注**；
- 基本信息修改走 **FIBD Head + 合规 + 法务** 审批后生效；
- 能力变动走 **渠道运营发起 → FIBD Head 审批**，审批后同步 **合规、产品、清算**；
- 基本信息与渠道能力两个模块的审批流相互独立。
