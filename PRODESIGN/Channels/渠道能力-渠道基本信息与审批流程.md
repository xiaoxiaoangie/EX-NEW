# 渠道能力：渠道基本信息、审批流程与能力维度

> 日期：2026-07-28 ｜ 文档类型：渠道管理 / 产品需求
> 关联：`EX OffRamp解决方案.md` 的 Case 5（渠道能力维护）引用本文档；本文档定义 **渠道基本信息（签约信息）模块**、**渠道信息的审批 / 变更流程** 与 **渠道能力（付款）维度**；渠道账户模块不在本文档展开。

---

## 一、定位

渠道信息管理拆为三个独立模块：

| 模块                                  | 内容                                                                       | 文档             |
| ------------------------------------- | -------------------------------------------------------------------------- | ---------------- |
| **① 渠道基本信息（签约信息）** | 渠道主体、我司主体、签约有效期、渠道提供服务、渠道牌照、附件协议 | **本文档** |
| **② 渠道能力**                 | 付款（法币 / 数币 / 人民币结汇）能力维度 + 异常处理                        | **本文档** |
| **③ 渠道账户**                 | 渠道账户结构与账户维度                                                     | 单独设计（后补） |

---

## 二、渠道整体流程（签约 → 维护 → 变更）

1. **FIBD 商务签约**：FIBD 完成商务谈判与签约，**确认渠道基本能力**（主体、牌照、服务范围）。
2. **渠道运营维护**：渠道运营基于签约结果，维护渠道**基本信息与具体能力**。
3. **信息变动流程**：渠道信息 / 能力变动后，需**同步产品经理、渠道运营、清算（对账）、合规、FIBD**；改动须走审批流（见第三节）。

---

## 三、渠道基本信息（签约信息）

### 3.1 字段定义

| 字段                   | 说明                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| **渠道主体**     | 渠道签约的法律主体                                                                               |
| **我司主体**     | 我司签约主体                                                                                     |
| **签约有效期**   | 合同起止日期                                                                                     |
| **渠道提供服务** | 渠道实际提供的服务范围，多选：**法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** |
| **渠道牌照**     | 渠道持有的牌照                                                                                   |
| **附件**         | 协议、补充协议等文件（非必填）                                                                   |

> **服务范围说明**：「渠道提供服务」是该渠道的能力清单上限——签约时确认的服务项，决定「渠道能力」模块中哪些能力允许维护；能力维度明细在能力模块中维护，本字段只做服务级勾选；

### 3.2 修改流程（基本信息审批流）

- **渠道运营修改 → FIBD Head 审批 → 合规审批、法务审批**。
- 基本信息（主体、牌照、有效期、服务范围）属**法律与合规层面信息**，必须经合规与法务审批后才生效。

---

## 四、渠道能力变动审批流

> 能力维度变动（如新增收款国家、调整限额、变更 POBO 规则等）走独立的审批流，与基本信息审批流分开。

- **渠道运营发起 → FIBD Head 审批** → 审批通过后**同步给合规、产品、清算**。
- 变动生效后同步范围：**产品经理、渠道运营、清算（对账）、合规、FIBD**。

### 两类审批流对比

| 项目                 | 渠道基本信息              | 渠道能力             |
| -------------------- | ------------------------- | -------------------- |
| **发起人**     | 渠道运营                  | 渠道运营             |
| **审批人**     | FIBD Head → 合规 → 法务 | FIBD Head            |
| **审批后同步** | 合规、法务                | 合规、产品、清算     |
| **性质**       | 法律 / 合规信息，重审批   | 业务运营信息，重同步 |

---

## 五、渠道能力（付款，分三类 + 异常处理）

> **范围**：本期只做「付款」渠道能力维护；收款、换汇能力后补。付款能力拆为 **法币付款 / 数币付款 / 人民币结汇（外汇管制国家）** 三类 + **异常处理**。
> **备注规则**：基本能力（法币 / 数币付款表内）、异常处理、人民币结汇申报信息 **各自有独立的备注字段**。

### 5.1 法币付款

| 维度                     | 取值 / 规则                                                                                                                                                                       |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **收款国家**       | 国家；**标记是否外汇管制国家**（管制国家需补充申报项，见 5.3）；多选支持 **支持国家（正向）/ 禁止国家（反向）** 两种配置模式，**只配置一种即可**                        |
| **商户主体所在国家** | 商户主体注册国家；多选支持 **支持国家（正向）/ 禁止国家（反向）** 两种配置模式，**只配置一种即可**                                                                        |
| **收款方式**       | **TT、LOCAL BANK TRANSFER、WALLET**                                                                                                                                         |
| **账户要求**       | 付款前需要先创建的账户形态：**创建子账户 / 使用单独的付款 VBA**；VBA 的使用范围：**仅用于付款 / 收付一体**（两者影响账户结构设计和资金归集方式）                      |
| 支付/清算系统            | 仅当收款方式 =**LOCAL BANK TRANSFER** 时启用：**CHATS、FPS、SEPA、SEPA Instant、ACH** 等<br />- 每个国家的支付/清算系统做基础数据<br />- 暂时不支持                   |
| **支持的行业分类** | **货物贸易、服务贸易**- 暂不支持                                                                                                                                            |
| **商户-收款人类型** | **B2B、B2C、C2B、C2C**（= 商户类型 → 收款人类型组合，与商户类型、收款人类型一起维护）                                                                                 |
| **支持的资金来源** | **平台结算款**（→ 选电商平台）；**线下贸易款**（无子选项）；**三方收单行结算款**（→ 选三方收单行，如 PayPal / Stripe / Airwallex 等）<br />- 资金来源暂不支持 |
| **收付款人关系**   | 按收付款人类型可选：**同名、股东、关联公司、供应商、广告服务商、物流服务商、员工、其他**- 同名和异名，异名的具体场景在推送渠道时映射                                        |
| **收款人报备开户** | 收款人**是否需要报备开户**：**需要 / 不需要**；选「需要」出现**文本框**，填写报备所需资料清单                                                                   |
| **支付限额**       | 限额多维度联动：按**收款方式 + Rails + 币种 + 商户-收款人类型 + 收款人类型 + 行业分类** 组合配置（B2C / B2B / C2C / C2B 限额可不同；不同币种、不同 Rails、不同收款人类型限额可不同）；**最大最小** |
| **是否支持 POBO**  | **是 / 否**；POBO 要求：**只能用入网商户信息 / 自定义**                                                                                                               |
| **备注**           | 自由备注（基本能力备注，独立于异常处理备注）                                                                                                                                      |

### 5.2 数币付款

| 维度                   | 取值 / 规则                                  |
| ---------------------- | -------------------------------------------- |
| **收款方式**     | **收款地址 / 数币钱包**                |
| **网络 / 币种**  | 支持的区块链网络、币种清单（USDT / USDC 等） |
| **收款地址类型** | 客户自有钱包地址 / 渠道生成地址              |
| **支付限额**     | 按网络 / 币种组合配置（最大最小）            |
| **是否支持承兑** | 数币直接付款 / 需要先承兑为法币再付          |
| **备注**         | 自由备注（基本能力备注，独立于异常处理备注） |

### 5.3 人民币结汇（外汇管制国家）

> 在法币付款基础上，针对**外汇管制国家**的**人民币结汇**场景**追加**以下项。

| 增项                       | 说明                                                              |
| -------------------------- | ----------------------------------------------------------------- |
| **申报人要求**       | 申报人国家（**默认 = 收款国家**）、**收款人证件类型** |
| **贸易背景申报要求** | 与「业务场景 + 资金来源」联动（见下表）                           |
| **备注**             | 自由备注（**申报信息独立备注**）                            |

**贸易背景申报（按资金来源联动）**

| 资金来源                            | 申报材料                                                                                                                    |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| **平台结算款 / 三方收单机构** | 平台 / 独立站**订单明细**                                                                                             |
| **线下贸易款**                | **PI、物流、提单、网站、报关单**；**可添加多行，一行可多选**；**行内多选 = OR 关系，多行之间 = AND 关系** |
| **备注**                      | 自由备注                                                                                                                    |

### 5.4 异常处理

> 针对付款失败后的资金退回规则；**异常处理有独立的备注字段**。

| 维度                       | 取值 / 规则                                                                                                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **付款失败资金退回** | 退回到：**大账户 / 商户账户**                                                                                                                                     |
| **退回币种**         | **多选**：渠道结算币种 / 收款人账户币种 / 付款钱包币种 / **自定义币种**                                                                                     |
| **退回金额**         | **单选**：**原金额** / **去掉手续费金额**；选「去掉手续费金额」出现一个**备注输入框**（不是手续费金额字段），供运营填写**手续费预计多少** |
| **备注**             | 自由备注（**异常处理独立备注**）                                                                                                                                  |

### 5.5 配置层级（树状）

- **渠道基本信息**：主体 / 我司主体 / 有效期 / 服务 / 渠道牌照 / 附件（修改走 FIBD Head + 合规 + 法务审批）
- **渠道能力 → 付款** → 拆为三类 + 异常处理
  - **法币付款** → 国家（支持 / 禁止）/ 商户主体所在国家（支持 / 禁止）/ 收款方式 / **账户要求** / Rails / 行业分类 / 商户-收款人类型 / 资金来源 / 关系 / **收款人报备开户** / 限额（多维联动）/ POBO / 备注
  - **数币付款** → 收款地址 / 数币钱包 / 网络币种 / 限额 / 备注
  - **人民币结汇（外汇管制国家）** → 法币付款全部 + 申报人要求 + 贸易背景申报 + 申报备注
  - **异常处理** → 资金退回位置 / 退回币种（多选）/ 退回金额（单选）/ 手续费备注 / 异常备注
- **渠道账户**：单独设计（本期留维度，账户模块后补）

## 六、验收标准

- 渠道基本信息可维护 **渠道主体 / 我司主体 / 签约有效期 / 渠道提供服务 / 渠道牌照 / 附件**；
- 「渠道提供服务」为 **法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** 六项多选；
- 付款能力可拆为 **法币 / 数币 / 人民币结汇** 三类分别维护，异常处理单独维护；
- 法币付款可维护 **账户要求**（子账户 / VBA，VBA 仅付款 / 收付一体）；
- **收款方式 = LOCAL BANK TRANSFER 才出现清算系统**；资金来源选「平台结算款 / 三方收单行结算款」时出现对应子选择；
- 收款国家标记为 **外汇管制** 时，自动追加申报人要求与贸易背景申报；
- 贸易背景申报「线下贸易款」支持 **多行 + 行内多选**，行内 = OR、行间 = AND；
- 收款国家与商户主体所在国家均可按 **支持国家（正向）/ 禁止国家（反向）** 配置，同一字段只配一种模式；
- 支付限额可按 **收款方式 + Rails + 币种 + 商户-收款人类型 + 收款人类型 + 行业分类** 组合生效（最大最小），不同组合限额可不同；
- 法币付款可维护 **收款人报备开户**（需要 / 不需要）；选「需要」可填写报备所需资料；
- 异常处理可维护 **退回位置 / 退回币种（多选）/ 退回金额（单选）**；选「去掉手续费金额」出现备注输入框；
- 基本能力、异常处理、人民币结汇申报信息 **各有独立备注**；
- 基本信息修改走 **FIBD Head + 合规 + 法务** 审批后生效；
- 能力变动走 **渠道运营发起 → FIBD Head 审批**，审批后同步 **合规、产品、清算**；
- 基本信息与渠道能力两个模块的审批流相互独立。
