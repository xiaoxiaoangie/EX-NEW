# 渠道能力：渠道基本信息、审批流程与能力维度

> 日期：2026-07-28 ｜ 文档类型：渠道管理 / 产品需求
> 关联：`EX OffRamp解决方案.md` 的 Case 5（渠道能力维护）引用本文档；本文档定义 **渠道基本信息（签约信息）模块**、**渠道信息的审批 / 变更流程** 与 **渠道能力（付款）维度**；渠道账户模块不在本文档展开。
> 交互稿：`渠道中心.html`（本文档结构与交互稿对应：侧边栏 = 渠道基本信息 / 渠道能力〔外币付款、人民币结汇、数币付款〕/ 渠道账户；模块可独立新增：新渠道先建基本信息再建能力，已有渠道可直接新增能力，能力 ≠ 必须建账户）。

## 一、定位

渠道信息管理拆为三个独立模块：

| 模块                                  | 内容                                                             | 文档             |
| ------------------------------------- | ---------------------------------------------------------------- | ---------------- |
| **① 渠道基本信息（签约信息）** | 渠道主体、我司主体、签约有效期、渠道提供服务、渠道牌照、附件协议 | **本文档** |
| **② 渠道能力**                 | 付款（法币 / 数币 / 人民币结汇）能力维度 + 异常处理              | **本文档** |
| **③ 渠道账户**                 | 渠道账户结构与账户维度                                           | 单独设计（后补） |

### 1.1 能力框架：四大块 + 字段两类用途

> 渠道能力的定位是**登记渠道的能力**，把已对接的大量 corridor 登记到系统上，供相关部门查看；**不含路由策略**（优先级 / 成本 / 分流）。

**能力四大块**：

| 块                        | 内容                                                        | 维护层级                          |
| ------------------------- | ----------------------------------------------------------- | --------------------------------- |
| **1) 渠道合规政策** | 支持 / 禁止国家，支持 / 禁止行业                            | 渠道级，对该渠道下所有能力生效    |
| **2) 具体付款能力** | 付什么国家、什么方式（清算系统）、限额、时效                | 能力条目级（渠道 + 支付方式）     |
| **3) 渠道账户体系** | 了解渠道的资金怎么走（账户结构 / 结算币种 / 资金路径）      | 渠道级（渠道账户模块）            |
| **4) 渠道资金处理** | 如：只能接受 USD 打过去；收款资金能否直接付款；异常资金处理 | 渠道级 / 能力级（异常处理随表单） |

**字段两类用途**：

| 类型           | 说明                                                                                    | 例子                                                             |
| -------------- | --------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| **登记** | 仅供 FIBD / 渠道运营 / 产品 / 渠道合规运营 / 合规官等相关人明确知道渠道能力，无系统逻辑 | 时效、限额、超限处理、账户要求、异常资金处理                     |
| **过滤** | 交易时参与过滤渠道，是渠道路由的第一部分（无具体路由策略）                              | 支持国家 / 行业、支付方式、币种、资金来源、B2B / B2C / C2B / C2C |

## 二、渠道整体流程（签约 → 维护 → 变更）

1. **FIBD 商务签约**：FIBD 完成商务谈判与签约，**确认渠道基本能力**（主体、牌照、服务范围）。
2. **渠道运营维护**：渠道运营基于签约结果，维护渠道**基本信息与具体能力**。
3. **信息变动流程**：渠道信息 / 能力变动后，需**同步产品经理、渠道运营、清算（对账）、合规、FIBD**；改动须走审批流（见第三节）。

---

## 三、渠道基本信息（签约信息）

### 3.1 字段定义

| 字段                   | 说明                                                                                             |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| **渠道名称**     | 渠道名称（如 ChannelPay），列表与能力模块均以此展示                                              |
| **渠道主体**     | 渠道签约的法律主体                                                                               |
| **我司主体**     | 我司签约主体（下拉选择）                                                                         |
| **渠道所在国家** | 渠道注册 / 展业所在国家；国家枚举值多，采用**模糊搜索 + 标签**选择                         |
| **签约有效期**   | 合同起止日期                                                                                     |
| **渠道提供服务** | 渠道实际提供的服务范围，多选：**法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** |
| **渠道牌照**     | 渠道持有的牌照                                                                                   |
| **附件**         | 协议、补充协议等文件（非必填）                                                                   |

> **服务范围说明**：「渠道提供服务」是该渠道的能力清单上限——签约时确认的服务项，决定「渠道能力」模块中哪些能力允许维护；能力维度明细在能力模块中维护，本字段只做服务级勾选；

### 3.2 修改流程（基本信息审批流）

- **渠道运营修改 → FIBD Head 审批 → 合规审批、法务审批**。
- 基本信息（主体、牌照、有效期、服务范围）属**法律与合规层面信息**，必须经合规与法务审批后才生效。

---

## 四、渠道能力变动审批流

> 能力维度变动（如新增收款国家、调整限额、变更 POBO 规则等）走独立的审批流，与基本信息审批流分开。

- **渠道运营发起 → FIBD Head 审批** → 审批通过后**同步给合规、产品、清算**。
- 变动生效后同步范围：**产品经理、渠道运营、清算（对账）、合规、FIBD**。

### 两类审批流对比

| 项目                 | 渠道基本信息              | 渠道能力             |
| -------------------- | ------------------------- | -------------------- |
| **发起人**     | 渠道运营/ FIBD            | 渠道运营             |
| **审批人**     | FIBD Head → 合规 → 法务 | FIBD Head            |
| **审批后同步** |                           | 合规、产品、清算     |
| **性质**       | 法律 / 合规信息，重审批   | 业务运营信息，重同步 |

### 5.1 公共规则（对三类能力生效）

- **数据粒度**：一条数据 = 渠道 + 支付方式（数币 = 渠道 + 收款方式）；编辑时唯一键不可修改；
- **层级模型**：支付方式 → 清算系统（Rail，可多个）→ 国家；每个清算系统独立配置国家 / 币种 / 行业 / 资金来源 / 商户-收款人类型 / 时效 / 限额；
- **默认 + 例外（继承覆盖）**：清算系统层配默认能力，国家只挂清单；个别国家例外覆盖（一期待定）；
- **字段两类用途**：登记（仅供相关人查看，无系统逻辑）/ 过滤（交易时参与渠道过滤，路由第一部分，无路由策略）；
- **资金处理与异常处理**仅作登记备案，系统不据此自动处理；
- 基本信息、付款能力、异常处理、申报信息**各自有独立的备注字段**。

### 5.2 角色分工（不同的人维护不同的内容）

| 角色 | 维护内容 | 层级 |
| --- | --- | --- |
| **合规（渠道合规运营 / 合规官）** | **合规政策**：支持 / 禁止国家，支持 / 禁止行业 | 渠道级，对该渠道所有能力生效 |
| **渠道运营** | **渠道能力**：支付方式、清算系统模块（国家 / 币种 / 资金来源 / B2X / 时效 / 限额 / 超限处理）、收款人报备、POBO | 能力条目级 |
| **产品** | **账户体系**：账户要求（子账户 / VBA、VBA 收付范围）；**维护字段「是否参与过滤」的标签** | 能力条目级 + 系统配置 |
| **清算（资金）** | **资金处理**：接受的打款币种、收款资金能否直接付款、付款失败资金退回规则 | 渠道级 / 能力级 |

> 交互上按角色分区展示，各角色只能编辑自己负责的分区；分区审批流细化见「待确认」。

## 六、验收标准（基本信息与总纲；能力明细验收见各子文档）

- 渠道基本信息可维护 **渠道名称 / 渠道主体 / 我司主体 / 渠道所在国家 / 签约有效期 / 渠道提供服务 / 渠道牌照 / 附件**；
- 「渠道提供服务」为 **法币付款 / VA 收款 / 换汇 / 人民币结汇 / 数币钱包 / 承兑** 六项多选；
- 付款能力拆为 **外币（法币）/ 数币 / 人民币结汇** 三类独立文档与交互分别维护；
- 能力表单按角色分区：**合规政策（合规）/ 渠道能力（渠道运营）/ 账户体系 + 过滤标签（产品）/ 资金处理（清算）**，各角色只能编辑自己负责的分区；
- 字段区分**登记 / 过滤**两类用途，页面以角标标识；「是否参与过滤」标签由产品维护；
- 基本信息修改走 **FIBD Head + 合规 + 法务** 审批后生效；
- 能力变动走 **渠道运营发起 → FIBD Head 审批**，审批后同步 **合规、产品、清算**；
- 基本信息与渠道能力两个模块的审批流相互独立。
